# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

Agente QA is a Streamlit app that uses the Gemini API (`google-genai`) to turn a User Story / requirements document (TXT, MD, PDF, DOCX) into a structured set of QA test cases, which the user can then review/edit in the UI and export as Excel (Azure DevOps-import format) and PDF.

See `docs/context.md` for the product objective, the current-state assessment, and the roadmap this codebase is being evolved towards (security hardening, modularization, multi-provider support, Markdown prompts, direct Azure DevOps integration, adaptable config). Read it before doing any non-trivial change — new work should move the code towards that target shape rather than adding more to the existing monolith.

## Commands

```bash
pip install -r requirements.txt
streamlit run app.py

pip install -r requirements-dev.txt
pytest -q
```

`GEMINI_API_KEY` is read from Streamlit secrets (`st.secrets`) first, then from the `GEMINI_API_KEY` env var, then falls back to a manual password field in the sidebar. For local runs, put it in `.streamlit/secrets.toml` (gitignored) rather than exporting it or typing it in the UI. `AZURE_DEVOPS_PAT` (the Azure DevOps personal access token, Fase 5) is resolved the same way via `secrets.resolve_secret(cfg.pat_secret_name)` — it must never be written into `config/azure_devops.yaml`; that file only names the secret (`pat_secret_name`), never its value.

Tests live under `tests/` (`pytest`, config in `pyproject.toml`, `testpaths = ["tests"]`). Every module under `agente_qa/` except `agente_qa/ui/` has at least one test file — no `streamlit.testing.v1.AppTest` coverage over `ui/*` yet. Fixtures: `tests/conftest.py` (`FakeUpload`, `sample_result`), `tests/fixtures/` (sample `.txt`/`.pdf`/`.docx`, `not_a_pdf.pdf`), `tests/fixtures/golden/` (frozen `create_excel` output per preset — regenerate deliberately, never hand-edit). There is no linter/formatter configured yet. Do not assume `ruff`/etc. exist — check before referencing them.

## Architecture

`app.py` is a thin Streamlit entrypoint (page config, session-state init, and calling the `agente_qa.ui.*` render functions in order). All logic lives in the `agente_qa/` package:

- `config.py` — `APP_VERSION`, `DEBUG` (from `AGENTE_QA_DEBUG` env var; gates showing technical error detail in the UI), `SCHEMA` (the JSON schema forced on the provider's structured output: `TEST_CASES` / `ALERTS` / `COVERAGE` — canonical/permissive on purpose, see "SCHEMA has Gemini's shape by accident" below), and `PROJECT_ROOT` (used to resolve `prompts/` and `fonts/` regardless of cwd). `AZURE_COLUMNS` / `MATRIZ_COLUMNS` / `EXCEL_CONFIGS` and `PROVIDERS` / `DEFAULT_PROVIDER` / `FALLBACK_MODELS` are no longer literals here: they're loaded from `config/*.yaml` via `settings.py` (`load_columns`/`load_excel_presets`/`load_providers`/`load_default_provider`) and re-exported under the same names, so callers don't change. `FALLBACK_MODELS` is kept for backward compatibility (`ui/sidebar.py` still imports it) but is now derived from `PROVIDERS[DEFAULT_PROVIDER]["fallback_models"]` instead of being a Gemini-only literal.
- `defaults.py` — the pre-Fase-3/4 literals for `AZURE_COLUMNS`, `MATRIZ_COLUMNS`, `EXCEL_CONFIGS`, `DEFAULT_PROVIDER`, `PROVIDERS`, kept verbatim as the fallback `settings.py` uses when the corresponding `config/*.yaml` is missing (a missing `config/` dir is a valid, functional state, not an error).
- `settings.py` — loads and validates the YAML config under `config/` at `PROJECT_ROOT`: `load_columns(path=None) -> ColumnSpec` (reads `config/columns.yaml`; hard-fails with `ConfigError` if `allow_override` is false and `azure_columns` differs from `defaults.AZURE_COLUMNS` — the approved-contract guard), `load_excel_presets(path=None) -> dict[str, ExcelPreset]` (reads `config/excel_presets.yaml`, validating each preset via `_validate_preset`: no missing/unknown keys, correct types, `sheet_name` non-empty/≤31 chars/free of `[ ] : * ? / \`, `base_id`/`base_testpoint` positive ints, `title_prefix` matching `^[A-Za-z0-9_-]*$`), `load_providers(path=None) -> dict[str, ProviderConfig]` / `load_default_provider(path=None) -> str` (read `config/providers.yaml`, validating each provider via `_validate_provider`: no missing/unknown keys, correct types, non-empty `secret_name`/`default_model`, positive `max_source_chars`, non-empty list of non-empty `fallback_models`; `load_default_provider` also hard-fails if the declared `default_provider` isn't a key in `providers`), and `load_azure_devops_config(path=None) -> AzureDevOpsConfig` (Fase 5; reads `config/azure_devops.yaml`, falls back to a disabled default `AzureDevOpsConfig` if missing; two hard-fails, in order: (1) the parsed YAML must not contain a literal `pat`/`token`/`password` key at *any* depth — checked recursively by `_find_forbidden_secret_key` — because the PAT value must never live in config, only its secret name (`pat_secret_name`); (2) `organization_url` must match `^https://(dev\.azure\.com/|[a-z0-9-]+\.visualstudio\.com)` — the highest-severity check in the whole roadmap, since the PAT is sent as an `Authorization` header to that URL and an unvalidated host could leak it). All four loaders fall back to `defaults.py` (or, for Azure DevOps, a disabled-by-default config) when their YAML file doesn't exist. `ExcelPreset`/`ColumnSpec`/`ProviderConfig`/`AzureDevOpsConfig` (frozen dataclasses, `.as_dict()` where applicable) are the typed shapes; `config.py` converts them back to the plain list/dict shape the rest of the app already expects.
- `errors.py` — exception hierarchy: `AgenteQAError` (base; `user_message` safe to display, `detail` technical-only, `code`), `SourceError` (upload/extraction), `ConfigError` (config loading, future), `ProviderError` (LLM provider base) with `QuotaError` / `TransientError` / `BadRequestError` subclasses (mostly future, `ProviderError` itself is raised today by `generation.py`), `IntegrationError` (future, e.g. Azure DevOps).
- `security.py` — `MAX_UPLOAD_BYTES` (10 MB), `ALLOWED_EXTENSIONS`, `validate_upload(name, data)` (size/extension checks, raises `SourceError`), `sniff_kind(data)` (detects pdf/docx/text from magic bytes/content, not filename), `redact(text)` (masks API-key/PAT-shaped tokens, absolute filesystem paths, `Authorization` headers — apply before logging or showing `detail`).
- `secrets.py` — `resolve_secret(name, default="")`: `st.secrets` (lazy import, tolerant of missing `secrets.toml`) → `os.environ` → default. The only module outside `ui/` allowed to import Streamlit.
- `utils.py` — field normalization helpers (`safe_text`, `safe_steps`, `normalize_coverage`, `normalize_validation_method`, `build_case_title`, `normalize_case_id`, `find_coverage`, `aggregate_case_alerts`) shared by the Excel/PDF exporters and the UI.
- `extraction.py` — `extract_source_bytes(name, data)`: pure core, calls `security.validate_upload` then dispatches on `security.sniff_kind` (not the extension) to decode text / parse PDF / parse DOCX; raises `SourceError` with a safe `user_message` and technical `detail`. `extract_source(uploaded_file)` is a thin wrapper (`uploaded_file.name` / `.getvalue()`) around it. PDF text extraction only (no OCR); DOCX also flattens tables into pipe-joined rows.
- `prompts.py` — prompts are `.md` files under `prompts/` (default: `prompts/qa_base.md`), not code. `list_prompts()` scans `prompts/*.md` (non-recursive, so it never lists anything under `prompts/.history/`); `load_prompt(name)` reads one (cached in a module-level dict, falls back to a short inline default if missing/empty); `save_prompt(name, content)` writes one and calls `clear_prompt_cache()`; `prompt_path()`/`is_valid_prompt_name()` restrict names to `^[A-Za-z0-9_-]+\.md$` so the editor UI can't write outside `prompts/` (no `/`, no `..`). Before overwriting, `save_prompt` snapshots the previous content to `prompts/.history/<name>.<version>.md` (`version` = a fresh `YYYYMMDDTHHMMSS` timestamp) and prunes old snapshots down to `MAX_VERSIONS = 20` per prompt. `list_prompt_versions(name)` / `read_prompt_version(name, version)` / `restore_prompt_version(name, version)` expose that history; `version` is validated against its own regex (`_VALID_VERSION`) completely independently of `is_valid_prompt_name` — the two are never combined into a path before both pass, which is what keeps the version parameter from becoming a second path-traversal vector. `qa_base.md` is the QA agent's system prompt: strict "don't invent anything, flag gaps as ALERTS, preserve source wording exactly" rules, ending in the required JSON output contract. New prompt variants just need a `.md` file dropped into (or saved via the UI into) `prompts/` — no code change, they appear in the selector automatically.
- `providers/base.py` — the provider contract (Fase 4): `GenerationRequest` (`prompt`, `source`, `schema`, `model`, `temperature`, `max_output_tokens`, all frozen-dataclass fields) and `GenerationResult` (`data`, `model`, `raw_text`) are the plain, provider-agnostic shapes crossing the boundary; `LLMProvider` is a `typing.Protocol` (`name`, `list_models()`, `default_models()`, `generate(request) -> GenerationResult`) any provider implements.
- `providers/__init__.py` — lazy provider registry: `_REGISTRY` maps a provider name to a dotted `"module:ClassName"` string, `list_providers()` lists registered names, `build_provider(name, api_key) -> LLMProvider` does the actual `importlib.import_module` + `getattr` + instantiate, only at call time (so a future provider with a missing dependency never breaks app startup) and raises `errors.ConfigError` for an unknown name or an import failure.
- `providers/gemini.py` — `GeminiProvider` (`name = "gemini"`), the only registered `LLMProvider` today (see `docs/context.md` §3 scope guard: no OpenAI/Anthropic provider implemented yet). `generate()` assembles the full prompt, calls `google-genai`, parses the JSON response (falling back to extracting a ```` ```json ```` fenced block), and classifies any exception via the private `_classify(exc) -> ProviderError` method: same substring checks as before Fase 4 (`"429"`/`"quota"`/`"resource exhausted"` → `QuotaError`; `"500"`/`"internal"`/`"503"`/`"unavailable"`/`"deadline"`/`"timeout"` → `TransientError`; `"400"`/`"invalid argument"`/`"unsupported"` → `BadRequestError`; anything unmatched also falls back to `BadRequestError`, preserving the old "no retry, try next model" behavior), never lets an exception escape untyped. `_to_provider_schema(schema)` is a no-op today (Gemini accepts the canonical `config.SCHEMA` as-is) — the extension point for a future stricter provider (e.g. OpenAI), not implemented. Module-level `get_valid_models`, `build_client`, `generate_once`, `extract_error_detail` remain as the thin, independently-testable wrapper around `google-genai` that `GeminiProvider` is built on. No Streamlit dependency.
- `generation.py` — `validate_qa_structure` and `generate_qa_data(prompt_text, source_content, provider, model_name, *, fallback_models=None, temperature=0.0, max_retries=2, initial_wait=10, max_source_chars=28000, sleep=time.sleep)`. Takes an already-constructed `LLMProvider` (never imports Gemini directly): builds the candidate model list (selected model first, then `fallback_models` or `provider.default_models()`), and branches by exception *type* — `QuotaError`/`TransientError` back off and retry the same model up to `max_retries`, then move on; `ProviderError` (e.g. `BadRequestError`) and `ValueError` (from `validate_qa_structure`) move to the next candidate immediately, no retry. Source text is truncated at `max_source_chars` (default 28,000) before sending. `sleep` is injectable so tests run instantly. No Streamlit dependency; raises `errors.ProviderError` (safe `user_message`, last errors as `detail`) when every candidate model fails.
- `export/excel.py` — `create_excel`, maps `TEST_CASES` into the `AZURE_COLUMNS` and `MATRIZ_COLUMNS` sheets using the selected `EXCEL_CONFIGS` preset.
- `export/pdf.py` — `create_pdf` and its `_pdf_*`/`_case_*` helpers, builds a ReportLab document summarizing coverage and cases.
- `integrations/azure_devops.py` — `AzureDevOpsClient` (Fase 5): a hand-rolled REST client over `requests` (no official SDK) for the Work Items API, auth via HTTP Basic (empty username, PAT as password — set once as `session.auth` in `__init__`, never interpolated into any string). `check_connection()` (`GET .../_apis/projects/{project}`), `find_test_case_by_title(title)` (WIQL `POST .../_apis/wit/wiql`, single-quotes escaped, returns the first matching id or `None`), `create_test_case(case, preset)` / `update_test_case(work_item_id, case)` (JSON-Patch bodies — `add/replace` ops for `System.Title`, `Microsoft.VSTS.TCM.Steps`, and `System.AreaPath`/`System.IterationPath` when configured), and `push_test_cases(result_json, preset, *, dry_run=True, on_progress=None, skip_title_match=False) -> PushResult` (iterates `TEST_CASES`; idempotent via a per-case `AzureWorkItemId` written back after create/update, with a WIQL-by-title fallback across sessions; `dry_run=True` makes **zero** network calls — it only classifies each case as create/update from whether `AzureWorkItemId` is already set, and reports via `on_progress(index, total, title, action)`). `_steps_to_xml(steps)` builds the `Microsoft.VSTS.TCM.Steps` XML blob (wraps each action/expected-result in `<DIV>...</DIV>` and HTML-escapes the combined string once — no network dependency, tested directly against string fixtures). **Scope correction vs. the original roadmap wording**: Test Points are *not* directly creable via the API — they only materialize when a Test Case is associated to a Test Suite inside a Test Plan. Split accordingly: **5a** (create/update Test Cases, implemented above) is the priority and is complete; **5b** is `add_to_test_suite(work_item_id)` (`POST .../_apis/testplan/Plans/{planId}/Suites/{suiteId}/TestCase`, requires `test_plan_id`/`test_suite_id`), implemented at the client level but with no dedicated UI button yet. A `429` response maps to `TransientError` (reused from `errors.py`), honoring `Retry-After` in `detail`. Every error that propagates out carries a `detail` already passed through `security.redact` — the PAT is never logged or shown.
- `ui/` — one render function per screen section, each taking/returning plain values instead of relying on shared globals: `state.py` (`init_session_state`), `sidebar.py` (`render_sidebar` → config dict incl. `provider` (currently always `config.DEFAULT_PROVIDER`) and `api_key`, resolved via `secrets.resolve_secret(PROVIDERS[provider]["secret_name"])` with a manual password-field fallback), `document.py` (`render_document_section` → source text, handles upload/paste; re-extracts on a SHA-256 hash of the uploaded bytes, not just the filename, so a different file with the same name isn't silently ignored; catches `SourceError` to show `user_message` — plus redacted `detail` under `config.DEBUG` — and falls back to a generic message for anything else), `prompt_editor.py` (`render_prompt_section` → selected prompt filename; selectbox over `list_prompts()` plus an in-app `.md` editor with "Editar"/"Vista previa" tabs — the preview tab renders the current textarea content with `st.markdown` at its default `unsafe_allow_html=False` — "save" and "save as new" buttons, and a history section (shown when versions exist) with a `list_prompt_versions` selectbox and a "Restaurar" button wired to `restore_prompt_version`), `generation_section.py` (`render_generation_section`, the "Generate" button builds the `LLMProvider` via `providers.build_provider(sidebar_config["provider"], sidebar_config["api_key"])` and drives `generate_qa_data` → `create_excel`/`create_pdf`; has a dedicated `QuotaError` warning branch plus the same typed-error pattern as `document.py`), `editor.py` (`render_case_editor`, the per-case edit form — `TestCaseId` is immutable, saving regenerates Excel/PDF), `results.py` (`render_results_section`, metrics + editor + downloads + JSON/preview — unchanged by Fase 5), `azure_section.py` (`render_azure_section(result_json, preset_key)`, Fase 5: only ever called from `app.py`, and only when `load_azure_devops_config().enabled` is true *and* `secrets.resolve_secret(cfg.pat_secret_name)` resolves to a non-empty value — re-checks both itself too, so it's safe to call directly. Flow: "Probar conexión" button → dry-run preview table (`st.dataframe`, built from `push_test_cases(..., dry_run=True)` via `on_progress`) → "Crear como nuevos (permitir duplicados)" checkbox → a separate explicit confirmation checkbox gates the real "Ejecutar push real" button, which calls `push_test_cases(..., dry_run=False, skip_title_match=allow_duplicates)`. Does not touch the Excel/PDF download buttons in `results.py`).

All state lives in `st.session_state` (`source_content`, `source_name`, `source_hash`, `result_json`, `excel_data`, `pdf_data`).

### Data flow

`uploaded file / pasted text` → `extraction.extract_source` → `generation.generate_qa_data` (prompt from `prompts.load_prompt(selected_prompt)` + source → an `LLMProvider` built by `providers.build_provider(name, api_key)`, currently always `GeminiProvider` → schema-validated JSON) → held in `st.session_state.result_json`, editable via `ui.editor` → `export.excel.create_excel` / `export.pdf.create_pdf` regenerated from the (possibly edited) result on every change.

### Things to preserve unless explicitly asked to change

- `AZURE_COLUMNS` / `MATRIZ_COLUMNS` header names — these match an existing Azure DevOps import format; renaming/reordering them breaks that import.
- `prompts/qa_base.md`'s "don't invent, flag with ALERTS, preserve exact wording" rules — these are QA-process requirements, not incidental prompt phrasing.
- The filename validation in `prompts.is_valid_prompt_name` — it's what stops the in-app prompt editor from path-traversing outside `prompts/`.
- Streamlit stays out of the core: only `agente_qa/ui/*` and `agente_qa/secrets.py` may import `streamlit`.
- `config/azure_devops.yaml` must never contain the PAT value — only `pat_secret_name`, the name of the secret to resolve at runtime. `settings.load_azure_devops_config` hard-fails (`ConfigError`) if the parsed YAML contains a `pat`/`token`/`password` key at any depth, and hard-fails if `organization_url` doesn't match `^https://(dev\.azure\.com/|[a-z0-9-]+\.visualstudio\.com)` — don't relax either check.
